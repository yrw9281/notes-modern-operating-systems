# 第 1 章導論：作業系統（§1.1–1.7）

> 依《Modern Operating Systems》第 4 版整理；以概念與比較為主。

## 1.1 作業系統是什麼

- **兩個互補觀點**
  - **延伸機器（抽象）**：將複雜、零碎的硬體介面包裝成易用且一致的抽象，例如用檔案操作取代直接控制磁碟。
  - **資源管理者**：追蹤、分配並保護 CPU、記憶體、I/O 裝置與資料，協調多個程式或使用者的競爭。
- **資源共享方式**
  - **時間多工**：輪流使用資源，例如多個程式輪流取得 CPU。
  - **空間多工**：同時各用一部分資源，例如多個程式各占部分記憶體或磁碟空間。
- 作業系統主要服務應用程式及其程式設計者；命令列、桌面等使用者介面則通常由 shell 或其他應用程式提供。
- 核心（kernel）是作業系統的重要部分，但作業系統與周邊系統軟體的界線不一定明確。

## 1.2 作業系統簡史

- **第一代（1945–1955，真空管）**：沒有作業系統；以機器語言或插線板操作，一次由人手動執行一個工作。
- **第二代（1955–1965，電晶體與批次）**：硬體較可靠，工作先集中成批；常駐監控程式依控制卡自動載入、執行下一個工作，減少人工操作造成的閒置。
- **第三代（1965–1980，積體電路與多工）**
  - 相容機種與多用途需求使 OS/360 等系統規模、複雜度大增。
  - **多道程式設計**：一個工作等待 I/O 時，CPU 執行另一個工作；需要記憶體保護。
  - **假脫機（spooling）**：先把輸入、輸出暫存至磁碟，讓慢速周邊與 CPU 作業重疊。
  - **分時**：CPU 快速輪替服務互動使用者；MULTICS 的設計影響後續系統。
  - UNIX 衍生出多個版本；POSIX 嘗試統一基本介面，MINIX、Linux 等亦沿用 UNIX 概念。
- **第四代（1980–至今，個人電腦）**：大型積體電路與微處理器使個人電腦普及；CP/M、MS-DOS、圖形介面、Mac OS、Windows 與 UNIX 系統相繼發展。
  - **網路作業系統**讓使用者登入遠端主機、存取遠端資源；各機仍維持自己的 OS。
  - **分散式作業系統**讓多台處理器看起來像單一系統，並由 OS 隱藏程式與檔案實際所在位置。
- **第五代（1990–至今，行動電腦）**：智慧型手機、平板等成為重要平台；Android、iOS 等 OS 須支援行動硬體與大量應用程式。

## 1.3 電腦硬體概要

- **CPU**
  - 執行「取指令、解碼、執行」循環；暫存器保存運算資料與狀態，PC 指向下一指令，SP 指向堆疊，PSW 保存狀態與模式等資訊。
  - **管線、超純量**提升指令吞吐量，也增加硬體與 OS 管理的複雜度。
  - **核心態／使用者態**限制一般程式可執行的操作；系統呼叫透過陷阱（trap）進入核心，硬體例外也會轉交 OS 處理。
  - **多執行緒、多核心**增加可並行的工作單位；OS 必須正確排程。GPU 擅長大量平行的小型運算。
- **記憶體階層**：暫存器、快取、主記憶體、磁碟；越靠近 CPU 通常越快、容量越小、每位元成本越高。
  - 快取保存常用資料；命中較快，未命中則須往較慢層級讀取。快取需決定何時載入、放哪裡，以及替換哪個項目。
  - RAM 斷電後失去資料；ROM、快閃記憶體等可保留資料。快閃記憶體可重寫，但寫入較慢且有擦寫壽命。
  - **虛擬記憶體**讓程式使用的位址空間與實體 RAM 分離；MMU 協助將虛擬位址轉成實體位址，OS 可在 RAM 與磁碟間換入、換出資料。
- **磁碟與 SSD**：傳統磁碟以磁片、磁軌、磁柱、磁區儲存資料；機械移動造成隨機存取延遲。SSD 以快閃記憶體儲存，沒有機械部件。
- **I/O**
  - 控制器操作實際裝置；**裝置驅動程式**把 OS 的通用要求轉成控制器命令。
  - 控制器暫存器可採記憶體映射或獨立 I/O 埠。
  - I/O 可用忙碌等待、**中斷**通知完成，或 **DMA** 在記憶體與裝置間搬運資料、降低 CPU 介入。
- **匯流排與開機**：多種匯流排連結 CPU、記憶體與裝置；隨插即用由系統協調裝置資源。開機時韌體檢查、設定硬體並載入開機程式，之後 OS 載入驅動程式、初始化系統並啟動登入介面或 GUI。

## 1.4 作業系統類型

- **大型主機**：批次、交易處理與分時並重，重視大量 I/O 與高吞吐量。
- **伺服器**：透過網路為多個使用者提供檔案、列印、Web 等服務。
- **多處理器**：管理多顆 CPU／核心，處理通訊、一致性與排程。
- **個人電腦**：以單一使用者體驗為主，通常支援多工。
- **手持裝置**：重視行動硬體、感測器與應用程式生態系。
- **嵌入式**：控制特定設備；通常只執行預先安裝的軟體。
- **感測節點**：資源、電力有限，常採事件驅動設計，並須容忍節點故障。
- **即時系統**：正確性也取決於是否按時完成；**硬即時**錯過期限不可接受，**軟即時**偶爾逾時可容忍。
- **智慧卡**：CPU、記憶體與供電能力極有限；若同時執行多個 applet，仍須排程與保護。

## 1.5 作業系統基本概念

- **程序（process）**：執行中的程式及其狀態、位址空間、開啟檔案等資源。程序被暫停時，OS 保存狀態以便稍後恢復；程序可建立子程序，並以 IPC、訊號等方式協作或通知。
- **位址空間**：程序可使用的位址範圍，需與其他程序及 OS 隔離；虛擬記憶體可讓位址空間不受實體 RAM 大小直接限制。
- **檔案與目錄**：以裝置無關的方式管理資料；目錄形成階層，路徑可為絕對或相對路徑。開檔時檢查權限並取得檔案描述元；掛載可把另一個檔案系統接入目錄樹。
  - 特殊檔案讓裝置可用類似檔案的方式存取；管線（pipe）以檔案讀寫的形式連接程序。
- **I/O 子系統**：統一管理裝置，並結合通用 I/O 軟體與個別驅動程式。
- **保護**：控制哪些使用者或程序可讀、寫、執行資源；UNIX 權限常分為擁有者、群組及其他使用者。
- **Shell**：使用者層的命令解譯器，不是核心本身；它使用 OS 服務來啟動程式與處理命令。
- **「個體發展重演系統演化」**：新硬體平台常因資源限制而重走舊路（例如先單工、後多工）；技術條件改變後，曾淘汰的設計也可能再次適用。

## 1.6 系統呼叫

- 系統呼叫是程式向核心請求服務的介面。程式通常呼叫函式庫包裝；包裝設定呼叫編號與參數，再以陷阱切換到核心，由核心分派處理，完成後回傳結果或錯誤。
- 呼叫可能等待 I/O 而阻塞；OS 可在此期間排程其他程序。呼叫者應檢查回傳值與錯誤。
- **POSIX 常見呼叫**
  - 程序：`fork` 建立子程序、`waitpid` 等待子程序、`execve` 換入新程式、`exit` 結束程序。
  - 檔案：`open`、`close`、`read`、`write`、`lseek`、`stat`。
  - 目錄／檔案系統：`mkdir`、`rmdir`、`link`、`unlink`、`mount`、`umount`。
  - 其他：`chdir`、`chmod`、`kill`（傳送訊號）、`time`。
- 函式庫 API 與核心系統呼叫不一定一對一；有些操作可在使用者空間完成。
- **Windows Win32 API**提供較穩定的程式介面，但呼叫數量多，且部分 API 不會進入核心；Windows 程式常採事件驅動。它與 POSIX 在程序、檔案與訊號等介面上有所不同。

## 1.7 作業系統結構

- **單體式（monolithic）**：大部分 OS 以單一核心程式在核心態執行，程序間直接呼叫，效率高；但耦合、維護與故障隔離較差，核心元件出錯可能拖垮整個系統。可用可載入模組擴充。
- **分層式（layered）**：每層只依賴較低層服務，抽象清楚、較易設計與除錯；分層邊界與額外呼叫可能帶來限制或成本。THE 系統由低至高分為：
  - **L0：處理器分配與多工**——管理 CPU，並在中斷或計時器到期時切換程序。
  - **L1：記憶體與磁鼓管理**——分配主記憶體，管理程序頁面在主記憶體與磁鼓間的移動。
  - **L2：操作員－程序通訊**——處理程序與操作員控制台的互動，讓每個程序彷彿有自己的控制台。
  - **L3：輸入／輸出管理**——管理 I/O 裝置與資料緩衝，提供較一致的 I/O 介面。
  - **L4：使用者程式**——執行應用程式，使用下層提供的處理器、記憶體及 I/O 服務。
  - **L5：操作員**——執行系統操作員程序。越高層越不必直接處理底層硬體細節。
- **微核心（microkernel）**：核心只保留排程、訊息傳遞、低階記憶體／中斷等必要機制；檔案系統、驅動程式等以使用者態服務執行。縮小核心可改善故障隔離與可靠性，但跨程序訊息傳遞可能增加成本。機制與政策也可分離。
- **用戶端－伺服器（client-server）**：用戶端（client）以訊息提出服務要求，伺服器（server）執行服務並回覆，例如應用程式向檔案伺服器請求讀檔。雙方可在同一台機器，也可分處網路兩端；用戶端不必知道服務是在本機或遠端。此模型常搭配微核心，但不以微核心為必要；訊息傳遞則會帶來通訊成本，並須考慮延遲與伺服器故障。
- **虛擬機器**：Hypervisor 將硬體多工成多個虛擬硬體環境，讓不同 Guest OS 共存。
  - **Type 1**直接運行於硬體；**Type 2**依賴 Host OS。Guest 的特權操作須由 Hypervisor 控制或模擬。
  - **半虛擬化**會修改 Guest OS 以配合虛擬化；JVM 則是另一種虛擬機器，用來執行可攜式位元碼。
- **Exokernel（外核心）**：核心直接分配並保護實體資源，讓使用者層 OS／函式庫自行提供抽象；減少虛擬機器式位址重新映射的額外層。
